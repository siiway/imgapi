# Contributing

ImgAPI is a FastAPI service that collects third-party random image APIs and exposes them as 302 redirect endpoints. The project is intentionally small: most contributions are source-plugin updates, documentation updates, validation fixes, or small runtime changes.

## Development Setup

Use Python 3.13 or newer for local development. The repository contains `.python-version` with `3.13`, and `pyproject.toml` currently requires Python `>3.13`.

Install dependencies with uv:

```bash
uv sync
```

If uv is not available, install from the exported requirements file:

```bash
python3 -m pip install -r requirements.txt
```

Run the service locally with the project entry point:

```bash
uv run main.py
```

Or run FastAPI directly:

```bash
uv run fastapi run --host 0.0.0.0 --port 9333
```

Local runtime configuration lives in `config.yaml`. It is ignored by git. See `config.py` and the README deployment section for supported options.

## Project Layout

- `main.py`: FastAPI app, routes, OpenAPI customization, fallback routes, static-file serving, and the service `VERSION`.
- `imgapi.py`: `ImageAPI` source declaration class and startup loader for enabled source plugins.
- `config.py`: Pydantic config models and `config.yaml` loading.
- `utils.py`: path, timing, User-Agent, and sync/async helper functions.
- `sites/`: source plugins. Files ending in `.py` are imported; files ending in `.py.disabled` are disabled.
- `sites.md`: source catalog and API notes for humans.
- `public/`: static files served through the fallback route.
- `prek.toml`: pre-commit hook configuration used by `prek`.

## Image Source Plugins

Each enabled source is a `sites/*.py` file that declares an `api = ImageAPI(...)` object. The loader imports every `.py` file in `sites/` except example files, so top-level code should stay simple and safe to run at startup.

Use `__name__` as the plugin id unless there is a specific reason not to. The filename becomes the source id, for example `sites/gallery-evilneur-org.py` becomes `gallery-evilneur-org`.

Prefer direct 302 image endpoints in runtime code. JSON endpoints are useful for documentation, debugging, or future work, but avoid fetching JSON at request time unless the source has no redirect/image URL option.

Set region flags deliberately:

- `cn=True` means suitable for mainland China deployments.
- `outseas=True` means suitable for overseas deployments.
- A source can set both flags if it is expected to work in both regions.

Supported handlers are:

- `auto`: used by `/image` when User-Agent detection falls back to source-side behavior.
- `horizontal`: used by `/image/h` and by `/image` for desktop/tablet User-Agents.
- `vertical`: used by `/image/v` and by `/image` for mobile User-Agents.
- `init`: optional sync or async setup function called at startup.

Handlers may be strings, sync callables, or async callables. Keep callables small and return a redirectable image URL string, or `None` to let ImgAPI try another source.

When adding or changing a source:

1. Add or update the `sites/*.py` plugin.
2. Update `sites.md` with the id, documentation or homepage, runtime image endpoint, and any useful JSON response example.
3. Use `curl` to confirm redirect behavior and JSON shape when the source exposes both.
4. Disable dead or unsuitable sources by renaming to `.py.disabled` instead of leaving broken enabled plugins.
5. Consider bumping `VERSION` in `main.py` when the runtime source set or API behavior changes.

## Validation

The preferred full validation command is:

```bash
prek run --all-files
```

The current hooks run basic file checks, Ruff lint with autofix, Ruff format, and Astral `ty` type checks. You can run the component checks directly while iterating:

```bash
ruff check .
ruff format .
ty check .
```

Before handing off a change, run these read-only checks when practical:

```bash
ruff check .
ruff format --check .
ty check .
prek run --all-files
```

If `ruff-format` or `end-of-file-fixer` modifies files, rerun `prek run --all-files` to verify the final state.

## Documentation

Keep README content focused on users deploying and calling the service. Keep source-specific details in `sites.md`. Keep contributor workflow details in this file.

When documenting image APIs in `sites.md`, include both the image endpoint and JSON endpoint if both exist. Runtime code should point at the image endpoint unless there is a concrete reason to parse JSON.

## Commit Hygiene

Do not include local runtime files, logs, caches, virtualenvs, or generated bytecode. Notable ignored paths include `config.yaml`, `*.log`, `__pycache__/`, and `*.local.*`.

Keep commits scoped to one logical change. If a formatting hook reformats many files, mention that in the commit or pull request summary so reviewers can separate behavior changes from mechanical formatting.
